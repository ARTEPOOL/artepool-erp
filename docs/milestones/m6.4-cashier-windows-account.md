## بالعربي، في سطور

- **الهدف:** الكاشير يفتح الجهاز، والبرنامج يفتح لوحده على شاشة الـ PIN، ويبيع. مفيش غير كده.
- **حساب ويندوز للكاشير** اسمه «الكاشير»: حساب عادي مش مدير، بيدخل لوحده لما الجهاز يفتح. كلمة سره عشوائية ومحدش بيشوفها، ومحفوظة في مخزن ويندوز المحمي.
- **قفل البرنامج** (شاشة الكاشير والـ PIN) زي ما هو بالظبط.
- **البيانات:** الكاشير ما يقدرش يفتح ولا يغيّر فولدرات البيانات والنسخ الاحتياطية والمفاتيح، ولا يوقّف السيرفر. ده بييجي من إن حسابه عادي مش مدير، وأنا هتأكد منه باختبار أوتوماتيك.
- **تحديثات ويندوز** ما تعيدش تشغيل الجهاز من 8 الصبح لـ 12 بالليل.
- **أداة الطوارئ:** زرار واحد «اعمل / صلّح حساب الكاشير»، ومتسجّل في سجل المراقبة.
- **لو شلت البرنامج:** الدخول التلقائي يقف، وحساب الكاشير يتعطّل (مش بيتمسح).
- **صحة النظام:** سطر واحد: «حساب الكاشير: تمام» أو «محتاج تصليح».
- **مش هنعمل دلوقتي:** قفل مدير المهام وشاشة الأوامر والإعدادات والمتصفح والإطفاء وتسجيل الخروج والفلاشات. نزودها بعدين لو ظهرت مشكلة حقيقية.

### حاجتين لازم يتعملوا عشان الكاشير «يدخل ويشتغل»

1. **تسجيل الجهاز مشترك بين الحسابين.** النهارده البرنامج بيحفظ تسجيل الجهاز (المفتاح اللي بيتكلم بيه مع السيرفر) **جوه حساب ويندوز اللي اتسجل منه**. لو الكاشير دخل بحساب جديد، البرنامج مش هيلاقيه وهيطلب تسجيل الجهاز من الأول. الحل: على جهاز السيرفر بس، التسجيل يتحفظ **للجهاز كله** في ملف محمي بمفتاح الجهاز، فالحسابين يستخدموه. أداة الطوارئ بتنقل التسجيل الحالي لوحدها، من غير ما تسجّل الجهاز تاني. ده كان مكتوب أصلاً في خطة M6.2 اللي وافقت عليها، بس ما اتعملش.
2. **طابعة الإيصالات بتتختار لكل حساب ويندوز.** بعد ما حساب الكاشير يتعمل، أول مرة بس: تدخل إنت بحسابك على البرنامج من شاشة الكاشير، وتختار طابعة الإيصالات (دقيقة واحدة). طابعة الملصقات محفوظة على السيرفر، فمش محتاجة حاجة.

### المميزات

- البيانات والنسخ والمفاتيح محمية من حساب الكاشير، حتى لو قفل البرنامج متوقف.
- الكاشير ما يقدرش يوقّف السيرفر، فاللابتوب ما يقفش فجأة.
- من غير Windows Pro.
- الكاشير ما يحسّش بأي فرق، وإنت كمان: كل اللي اتغيّر إنك بتدخل بـ «تبديل المستخدم».
- قليل الأجزاء، فقليل المشاكل.

### العيوب

- الكاشير لسه يقدر يفتح برامج ويندوز العادية (مدير المهام، الإعدادات، المتصفح) لو طلع برّه البرنامج. بس ما يقدرش يوصل للبيانات ولا يوقّف السيرفر ولا يسطّب برامج للجهاز كله.
- عشان تشتغل على جهاز المحل نفسه: Ctrl+Alt+Del ← «تبديل المستخدم» ← حسابك.
- كلمة سر حساب ويندوز بتاعك بتبقى مفتاح الجهاز: اكتبها واحفظها في الخزنة.
- كلمة سر حساب الكاشير محفوظة على الجهاز عشان الدخول التلقائي. هي محمية، والحساب ده أصلاً ما لوش صلاحيات.
- لو تحديث ويندوز بوّظ الدخول التلقائي (نادر): الجهاز يقف على شاشة دخول ويندوز، تدخل حسابك وتدوس «اعمل / صلّح» في أداة الطوارئ.
- جهاز المحل الحالي: مرة واحدة من أداة الطوارئ (حوالي 5 دقايق).

## 1. What changes on the POS/server PC

| | Today | After M6.4 |
|---|---|---|
| Windows accounts | The owner's (administrator) only | The owner's **and** a standard **cashier account** `artepool-pos` («الكاشير») that signs in by itself at start-up |
| At start-up | Windows signs in to the owner's account | The cashier account signs in by itself; the app's existing sign-in task starts it on the PIN screen, kiosk lock on (0082, 0090) |
| The owner at that PC | Signs in normally | Ctrl+Alt+Del → **Switch user** → the owner's account; the cashier's session and an open shift keep running |
| Data, backups, secrets, logs (`C:\ProgramData\ARTEPOOL\…`) | Closed to all but SYSTEM, Administrators and the services (M6.2 part F) | Unchanged; **verified** for the cashier account (health line and CI) |
| The services | Only administrators can stop them (Windows default) | Unchanged; **verified** for the cashier account |
| Windows Update restarts | Windows default | **Active hours 08:00–24:00** |
| The PC's enrollment (device key, server address, CA) | In the Windows account's Credential Manager | On the server PC: **one file for the whole PC** (`ProgramData\ARTEPOOL\device`, DPAPI machine key), shared by the owner's and the cashier's accounts. Office PCs and the laptop: unchanged |
| The kiosk lock (M5c, 0089, 0091) | As built | Unchanged |

**Not in M6.4 (owner, 2026-11-04):** no Task Manager, Run, command prompt, PowerShell, registry, Control Panel/Settings, browser, shutdown, sign-out/lock or USB limits. They can be added later if a real problem appears.

## 2. How

All of it is done by the service launcher (`artepool-svc`, already installed on the server PC, run as administrator):

```
artepool-svc cashier-account check | setup | disable
```

### `setup` (set up or repair; safe to run again)
1. **The account** `artepool-pos`, full name «الكاشير»:
   - a **standard user**: member of *Users* (S-1-5-32-545) and never of *Administrators* (S-1-5-32-544), both found by SID so an Arabic Windows works too; removed from Administrators if someone added it;
   - enabled; its password never expires and the user cannot change it.
   - Windows APIs present on Home: `NetUserAdd`, `NetUserSetInfo`, `NetLocalGroupAddMembers` / `NetLocalGroupDelMembers`.
2. **The password:**
   - 32 random characters from the system's secure random generator, new at every `setup`;
   - never shown, logged or written to a file;
   - kept only as the Windows LSA secret `DefaultPassword` (`LsaStorePrivateData`), as Microsoft's Autologon tool does; any plain-text `DefaultPassword` registry value is deleted.
3. **Automatic sign-in:** `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon`: `AutoAdminLogon=1`, `DefaultUserName=artepool-pos`, `DefaultDomainName=<this PC>`; `AutoLogonCount` removed.
4. **The app on the PIN screen:** nothing new. The app's sign-in task (M6.2 part F5) already starts it for any person who signs in, as that person; on a POS PC it opens in the kiosk lock.
5. **The shared enrollment:** the folder `ProgramData\ARTEPOOL\device` (SYSTEM and Administrators full; Users read and change, needed for the device key's renewal). The app keeps the enrollment there when the folder exists; elsewhere it keeps using Credential Manager.
6. **Active hours:** Windows Update's own settings (the place the Settings app writes), 08:00 to 24:00, automatic adjustment off.

### The enrollment move (existing shop PC)
- The emergency tool runs as the owner, so after `setup` it moves the owner's enrollment from his Credential Manager to the shared file, then removes the old copy. No new enrollment, same device, same drawer.
- The app does the same at start if it finds the folder and no shared file yet (a safety net).
- A new installation creates the folder, so the first-run wizard writes the shared file directly.

### `check` (read only)
Returns JSON with each item and its state:
- the account exists, is enabled, standard (Users, not Administrators), password never expires;
- automatic sign-in to it, the LSA secret present (never its value), no plain-text password;
- the folders `data`, `secrets`, `backups`, `wal`, `logs`, `config`, `setup`: no rule allows the cashier account, *Users*, *Authenticated Users*, *Everyone* or *Interactive*;
- the three services: none of those may stop, pause or reconfigure them;
- the shared enrollment present; active hours 08:00–24:00.

Result: `ok`, `repair` (the account exists, something is missing, each item named) or `not_set_up`.

### `disable` (uninstall)
Automatic sign-in off, the LSA secret deleted, the account **disabled, not deleted**. A reinstall then `setup` turns it on again.

### The emergency tool
- One card «حساب الكاشير في ويندوز» with the state and one button **«اعمل / صلّح حساب الكاشير»**.
- It runs `setup`, moves the enrollment, then `check`.
- It writes one audit entry (the Windows administrator who ran it, the PC, the result, each item) and updates the health line at once.

### System health → Server PC
- One line: **«حساب الكاشير: تمام»** / **«محتاج تصليح — افتح أداة الطوارئ»** (the missing items listed) / **«مش متعمل»**.
- The updater's SYSTEM run (already every minute) runs `check` once an hour and saves the result in `ops.server_health`, only when it changes. The server reads it from there; the server's own account needs no new rights.

### Uninstall
The server setup's uninstall runs `disable` before removing the programs (data and the account kept).

## 3. Tests

**Rust units (Linux and the Windows target):**
- the plan of `setup` and `disable` as pure data: the account flags, the registry values, never anything under the owner;
- the password: length, secure random source, never in any output;
- reading a folder's or a service's rules: allowed vs too open for the cashier;
- reading the observed state into `ok` / `repair` / `not_set_up`.

**Server (Vitest):**
- the emergency action writes the audit entry and the health state;
- the health line from the saved state;
- the migration's privileges (the updater may write only those columns).

**Desktop (Vitest, Arabic and English):** the emergency card and the health line.

**Windows CI (`test-install.ps1`, GitHub's Windows runner):**
1. Install, then `setup`, then `check` is `ok`: the account in Users and not in Administrators; `AutoAdminLogon=1` with the right name; **no** `DefaultPassword` value in the registry; active hours 8 to 0.
2. **As the cashier** (the test sets a known password for this step only, then `setup` makes a new random one), each of these must fail:
   - reading and writing in `data`, `secrets`, `backups` and `logs`;
   - writing in `C:\Program Files\ARTEPOOL`;
   - `sc stop` of each of the three services.
3. Uninstall: automatic sign-in off, the LSA secret gone, the account disabled. Reinstall, `setup`: on again.
4. `setup` twice in a row: still `ok`.

**By hand on the test VM** (a new section in `vm-test-part-f.md`): restart → the cashier signs in by itself → PIN screen full screen → sell → Switch user → the owner → the app works for the owner too → uninstall → the PC starts on the owner's sign-in again.
