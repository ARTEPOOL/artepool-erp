## بالعربي، في سطور

- جهاز الكاشير (وهو نفسه السيرفر) بيبقى عليه **حسابين ويندوز**:
  - **حساب الكاشير:** حساب عادي مش مدير، وبيدخل لوحده لما الجهاز يفتح.
  - **حسابك إنت:** مدير، بكلمة سر محدش يعرفها غيرك.
- حساب الكاشير مقفول عليه:
  - مدير المهام (Ctrl+Shift+Esc)، وصندوق Run، وشاشة الأوامر، وPowerShell، ومحرر الريجستري، ولوحة التحكم والإعدادات؛
  - قفل ويندوز وتسجيل الخروج، عشان الكاشير ميتقفلش برّه حسابه.
- الكاشير **ميقدرش يفتح** فولدرات البيانات والنسخ والمفاتيح، **ولا يوقّف** السيرفر.
- كل ده **من غير Windows Pro**: بيتكتب في الريجستري، وده شغال على Home.
- كلمة سر حساب الكاشير:
  - بتتعمل عشوائية وطويلة، ومحدش بيشوفها؛
  - بتتحفظ في مخزن ويندوز المحمي (LSA)، **مش نص مكشوف** في الريجستري.
- **جهاز جديد:** صفحة في التسطيب «اعمل حساب الكاشير» (متعلّم عليها من الأول).
- **جهاز المحل الحالي:** التحديث الأوتوماتيك **مش هيعمله لوحده**. إنت تعمله مرة واحدة من **أداة الطوارئ**.
- لما تقفل قفل البرنامج (القرار 0089)، قيود ويندوز دي **بتفضل** زي ما هي.
- «صحة النظام» هيقولك:
  - هل حساب الكاشير مظبوط؛
  - هل الهارد متشفّر (نصيحة بس، مش شرط).

## 1. What changes for the shop

| On the POS/server PC | Today | After M6.4 |
|---|---|---|
| Windows accounts | The owner's account only (administrator) | The owner's administrator account **and** a standard **cashier account** that signs in by itself at start-up |
| At start-up | Windows asks for the owner's sign-in | The cashier account signs in by itself; the app opens full screen on the PIN screen (0082, 0090) |
| The owner at the PC | Signs in normally | Ctrl+Alt+Del → **Switch user** → the owner's account. The cashier's session (and an open shift) keeps running |
| Task Manager, Run, command prompt, PowerShell, registry editor, Control Panel / Settings | Available | Turned off **for the cashier account only** |
| Windows lock, sign out, change password | Available | Turned off for the cashier account: the app has its own lock (0090). A Windows lock would shut the cashier out of their own session, because they do not know its password |
| Data, backups, keys, logs (`C:\ProgramData\ARTEPOOL\…`) | Closed to everyone but SYSTEM, Administrators and the services (M6.2 part F) | Unchanged; the cashier account is checked against them |
| The services | Only administrators can stop them (Windows default) | Unchanged; checked as the cashier |
| USB autorun | Windows default | Off for the cashier account |
| Restarts after Windows updates | Windows default | Windows Update **active hours** set to the shop's hours (0106) |
| Disk encryption | — | System health says: encrypted / not encrypted (recommended) / not available on this PC. Advice only, never blocking (0106) |
| The kiosk lock turned off (0089) | Only the app lock is lifted | Unchanged: the Windows limits stay |

What M6.4 does **not** do:
- No Windows shell replacement, Assigned Access or Group Policy (0082, 0106).
- The cashier can still open ordinary allowed programs from the Start menu (for example the browser, unless question 3 below blocks it). They cannot reach the shop's data, the keys or the services, and cannot install programs for all users.

## 2. How (every edition: Home and Pro)

All of it is done by the **service launcher** (`artepool-svc`, Rust, already signed into the installation and run as administrator). It runs a new command:

```
artepool-svc cashier-account check | create | repair | disable | remove
```

- `create` / `repair` (idempotent):
  1. **The account:**
     - Windows user name `artepool-pos`, shown as «الكاشير» (question 1);
     - **standard user**: member of *Users* (S-1-5-32-545) only, never *Administrators*, checked by SID, not by group name, so Arabic Windows works too;
     - password never expires, and the user cannot change it.
     - Windows APIs `NetUserAdd` / `NetUserSetInfo` / `NetLocalGroupAddMembers`, present on Home.
  2. **The password:**
     - 32 random characters from the system's secure random generator;
     - never shown, never logged, never stored in a file;
     - kept only as the Windows LSA secret `DefaultPassword` (`LsaStorePrivateData`), the way Microsoft's own Autologon tool does it.
     - Any old plain-text `DefaultPassword` value in the registry is deleted.
     - `repair` makes a new password.
  3. **Automatic sign-in:**
     - `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon`: `AutoAdminLogon=1`, `DefaultUserName=artepool-pos`, `DefaultDomainName=<this PC's name>`;
     - on Windows 11, the "Windows Hello only" switch is checked, because it can hide automatic sign-in for Microsoft accounts. The cashier account is a local account, so it is unaffected; the VM test confirms it.
  4. **The account's own limits.** The account's profile is created (`CreateProfile`, present on Home), its registry file (`NTUSER.DAT`) is loaded, and these values are written for that account only, never machine-wide, so the owner's account keeps everything:

     | Key under the cashier's `HKCU\Software\…` | Values |
     |---|---|
     | `Microsoft\Windows\CurrentVersion\Policies\System` | `DisableTaskMgr=1`, `DisableRegistryTools=1`, `DisableLockWorkstation=1`, `DisableChangePassword=1` |
     | `Policies\Microsoft\Windows\System` | `DisableCMD=2`: no interactive command prompt; scripts started by Windows itself keep working |
     | `Microsoft\Windows\CurrentVersion\Policies\Explorer` | `NoRun=1`, `NoControlPanel=1` (Control Panel and Settings), `NoLogoff=1`, `NoDriveTypeAutoRun=255`, `NoWinKeys=1`, `NoClose=1` (question 2), `DisallowRun=1` with the list below |
     | `…\Policies\Explorer\DisallowRun` | `powershell.exe`, `powershell_ise.exe`, `pwsh.exe`, `cmd.exe`, `wt.exe`, `regedit.exe`, `mmc.exe`, `taskmgr.exe`, `msconfig.exe`, `control.exe` (and `msedge.exe` if question 3 says so) |
     | `Control Panel\Desktop` | no secure screen saver (`ScreenSaverIsSecure=0`): the app's own lock is the lock |

     `DisallowRun` only stops programs started from Explorer (the Start menu, double-click). It is an extra layer, not the main one; the folder rules and the standard account are what protect the data.
  5. **Fast user switching** stays on, so the owner can sign in on top of the cashier.
- `check` returns the observed state as JSON: account exists, standard, enabled, automatic sign-in, LSA secret present (never its value), each limit value, and whether the cashier can open the protected folders (an access check against their SID).
- `disable` (used by uninstall): automatic sign-in off, the LSA secret deleted, the account disabled (not deleted). A reinstall turns it back on with `repair`.
- `remove` (emergency tool only, with a reason): the account and its profile deleted.

**Where it is started:**
- **New installation** (`ARTEPOOL-Server-Setup`):
  - a new installer page «حساب الكاشير في ويندوز / The cashier's Windows account», with the box «اعمل حساب الكاشير (مستحسن)» ticked;
  - silent installs take `/CASHIER=1|0`;
  - the step runs after the services are up, and is written to the install log (without the password, of course).
- **The PC already in the shop:**
  - an update never creates the account by itself, because it would change how the PC starts without the owner there;
  - the **Emergency tool** (0107, server PC, administrator prompt) gets a new card «حساب الكاشير في ويندوز»;
  - the card shows the state of each item (✓ / ✗) and has the buttons «اعمله» / «صلّحه» / «وقّفه» / «امسحه» (the last two with a reason).
- **Uninstall:** `disable` (question 5).
- **Audit:** every create, repair, disable and remove from the emergency tool is written to the audit log, with the Windows administrator who ran it, the PC and the reason.

**Health (System health → Server PC):**
- **The cashier account:** set up and complete / missing items, each named / not set up → «افتح أداة الطوارئ».
  - The updater's daily SYSTEM run writes the result of `check` to `updates\cashier-account.json`, and the server reads it.
  - The service account does not need any new rights.
- **Disk encryption:** BitLocker or Device encryption on the system disk: on / off (recommended) / not available. Read by the same daily run. Advice only.
- **Windows Update active hours:** set at installation and repaired by the daily run (question 4).

## 3. Tests

**Unit tests (Rust, Linux and the Windows target):**
- the list of limit values, written for the cashier and never under `HKLM` or the owner;
- the password rules (length, secure random source, never in the output of `check`);
- reading the observed state into "complete / missing";
- the uninstall plan;
- the installer's switch.

**Windows CI (`test-install.ps1`, on the GitHub Windows runner):**
1. Silent install with `/CASHIER=1`, then check:
   - the account exists, is enabled, is in *Users* and not in *Administrators*, and its password never expires;
   - `AutoAdminLogon=1`, the right user name, **no** `DefaultPassword` value in the registry;
   - the LSA secret is present (`check`);
   - the limit values are in the cashier's registry file, and absent from the owner's and from `HKLM`.
2. Act **as the cashier.** The test sets a known password just for this step, then `repair` makes a new random one. Each of these must fail:
   - opening `data`, `.secrets`, `backups` and `logs`;
   - writing in `C:\Program Files\ARTEPOOL`;
   - `sc stop` of each service;
   - starting `taskmgr`, `regedit` and `cmd` (interactive).
3. Uninstall, then check: automatic sign-in off, LSA secret gone, account disabled. Reinstall, then check: `repair` turns it back on.
4. `repair` twice in a row changes nothing else (idempotent).

**By hand on the test VMs (Windows 11 Home first, then 10 Home and 11 Pro):** a new section in the VM checklist:
- restart → the cashier signs in by itself → PIN screen full screen;
- Ctrl+Shift+Esc → "Task Manager has been disabled by your administrator";
- Win+R does nothing; the command prompt says it is disabled;
- Settings and Control Panel are refused;
- Ctrl+Alt+Del shows **Switch user** only (plus Shut down if question 2 allows it) → the owner signs in → everything works for the owner;
- the kiosk lock turned off from Settings → Devices → the Windows limits are still there;
- File Explorer → `C:\ProgramData\ARTEPOOL\data` → "You don't currently have permission";
- a USB stick does not start anything by itself;
- uninstall → the PC starts on the owner's sign-in again.

**Desktop unit tests (Arabic and English):** the emergency tool's new card, and the two new health lines.

## 5. Questions for the owner (with my recommendation)

1. **The account's name:** user name `artepool-pos`, shown on the Windows screen as «الكاشير». *Recommended as written.*
2. **May the cashier shut down or restart the PC from Windows?** This PC is also the server, so shutting it down stops the laptop too. *Recommended: no (the Shut down button is hidden for the cashier; the power button and the UPS stay; the owner shuts down from their own account).*
3. **Block the internet browser (Edge) for the cashier?** The app itself does not need it. Connecting Google Drive would then be done from the owner's Windows account. *Recommended: yes.*
4. **The shop's hours for Windows Update** (Windows waits for outside these hours before restarting; at most 18 hours): *proposed 08:00–24:00.*
5. **Uninstall:** turn automatic sign-in off and **disable** the cashier account (not delete it). *Recommended.*
6. **The PC already in the shop:** after this version, you set up the cashier account once from the **Emergency tool** (5 minutes, the guide shows how). *Recommended.*

## 6. Not in M6.4

- A second POS PC (0087): the same command is reused when it comes (the office installer offers it for a PC enrolled as POS).
- Blocking Microsoft Store apps, or limiting websites: possible later if needed.
